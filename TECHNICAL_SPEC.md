# Техническое задание: «Мой бюджет»

ТЕХНИЧЕСКОЕ ЗАДАНИЕ

Веб-сервис «Мой бюджет» — персональный финансовый трекер

Версия 1.0  •  MVP  •  Документ для передачи разработчику / Codex

## 1. Назначение и границы проекта

Создать самостоятельное русскоязычное веб-приложение для ежедневного учёта личных доходов, расходов, переводов, счетов, месячных бюджетов и финансовых целей. Пользователь должен быстро вводить операции, видеть актуальные остатки и анализировать финансовое поведение.

Целевая аудитория: частные пользователи без специальных финансовых знаний.

MVP: один локальный пользователь; без регистрации, облачной синхронизации и подключения банков.

Валютная модель MVP: только RUB, все суммы хранятся в целых копейках.

Интерфейс адаптивный для мобильных устройств, планшетов и компьютеров.

## 2. Технологический стек и архитектура

| Слой | Технологии |
| Frontend | React, TypeScript (strict), Vite, Tailwind CSS, Recharts |
| Backend | Node.js, Express, REST API, Zod |
| Данные | SQLite, Prisma, миграции |
| Проверки | Vitest, Playwright, ESLint, Prettier |
| Развёртывание | Docker Compose, локальный запуск |
| Форматы | JSON, CSV, XLSX |

Клиент взаимодействует с сервером через REST API /api/v1. Все критичные правила проверяются сервером. Сервер вычисляет остатки и агрегаты; клиент отображает результаты. По умолчанию сервер доступен только на 127.0.0.1.

## 3. Дизайн и навигация

Визуальный стиль: современный финансовый SaaS; светлая тема #F8FAFC, белые карточки радиусом 12–16 px, синий акцент #2563EB, доходы #16A34A, расходы #DC2626, предупреждения #F59E0B. Шрифт Inter с кириллицей; альтернативный системный шрифт. Светлая и тёмная темы.

Разделы: Главная (/dashboard), Операции (/transactions), Счета (/accounts), Бюджеты (/budgets), Цели (/goals), Аналитика (/analytics), Настройки (/settings).

Адаптивная навигация: боковое меню на широком экране и компактное меню на мобильном.

Минимальная поддерживаемая ширина — 320 px. Управление клавиатурой, видимый фокус, контрастность и понятные ошибки.

Состояния каждого экрана: загрузка, пустые данные, ошибка запроса, успешное сохранение.

## 4. Функциональные требования

### 4.1. Главная панель

Выбор месяца и года; по умолчанию текущий месяц.

Карточки: общий баланс всех активных счетов, доходы за месяц, расходы за месяц, денежный поток (доходы минус расходы).

Столбчатый график доходов и расходов за последние шесть месяцев; круговая диаграмма структуры расходов.

Пять последних операций с переходом к редактированию.

Прогресс месячных лимитов и предупреждения при достижении порогов.

Кнопка быстрого добавления операции; все данные поступают из API, не из статических заглушек.

### 4.2. Операции

| Поле | Формат / проверка |
| Тип | Доход / Расход / Перевод |
| Сумма | Положительное число, не более двух знаков после запятой |
| Дата | YYYY-MM-DD; по умолчанию текущая |
| Категория | Обязательна для дохода/расхода, отсутствует у перевода |
| Счёт | Обязательный исходный счёт |
| Счёт получателя | Обязателен для перевода; отличается от исходного |
| Комментарий | Необязательный, до 500 символов |

Создание, редактирование, удаление с подтверждением, фильтры по периоду, типу, категории, счёту, диапазону суммы, поиск по комментарию, сортировка и серверная пагинация. Доход увеличивает баланс; расход уменьшает; перевод одновременно уменьшает один счёт и увеличивает другой, не входя в доходы/расходы. При изменении или удалении операции все агрегаты пересчитываются.

### 4.3. Счета и категории

Счета: наличные, дебетовая карта, накопительный счёт, прочее. Поля: название, тип, начальный баланс, активность, дата создания. Баланс вычисляется по истории, не хранится как второе изменяемое поле. Архивные счета сохраняют историю, но не используются в новых операциях.

Категории доходов: зарплата, подработка, подарки, проценты, прочее. Категории расходов: продукты, жильё, транспорт, здоровье, развлечения, покупки, образование, прочее. Поддержать создание, изменение названия/цвета/иконки и архивирование. Категорию с историей нельзя физически удалить без переноса связанных операций.

### 4.4. Месячные бюджеты

Пользователь задаёт лимит расходов по категории на конкретный месяц. Остаток = лимит − сумма расходов; использование (%) = расходы / лимит × 100. Менее 80% — норма; от 80% до менее 100% — предупреждение; от 100% — достигнут или превышен. Полоса ограничивается 100%, текст показывает реальный процент. При лимите 0 процент не рассчитывается. Лимиты разных месяцев независимы.

### 4.5. Финансовые цели

Цель: название, целевая сумма, срок, описание, цвет, необязательная ссылка на накопительный счёт, статус. Взносы: дата, сумма, история, редактирование/отмена. Взнос — виртуальное распределение накоплений, не операция дохода или расхода и не списание со счёта. Накопленная сумма не может быть отрицательной. Прогресс = накоплено / цель × 100%; при 100% статус «Достигнута», превышение допустимо.

### 4.6. Аналитика

График доходов и расходов по месяцам; структура расходов по категориям; топ-5 категорий.

Средние расходы в день; сравнение выбранного периода с предыдущим периодом той же длительности.

Историческая динамика остатков по счетам на основе дат операций.

Если значение предыдущего периода равно нулю, выводить «Нет базы для сравнения», не бесконечный процент.

Все агрегаты фильтруются по датам операций, а не по времени записи в базу.

### 4.7. Импорт, экспорт и восстановление

CSV: UTF-8 BOM, разделитель «;», заголовки на русском, даты ДД.ММ.ГГГГ, суммы с двумя десятичными знаками.

XLSX: листы «Операции», «Счета», «Категории», «Бюджеты», «Цели», «Сводка», числовые форматы и фильтры.

JSON: полная резервная копия всех сущностей и связей с версией схемы.

Восстановление: проверка файла, предварительный просмотр, подтверждение, атомарная замена данных или полный откат.

Импорт CSV: собственный формат операций; ошибки строк показывать в отчёте. Предотвращать CSV/XLSX formula injection.

## 5. Модель данных

| Сущность | Поля |
| Account | id, name, type, openingBalanceKopecks, isActive, createdAt |
| Category | id, name, type, color, icon, isArchived |
| Transaction | id, type, amountKopecks, date, accountId, categoryId, destinationAccountId, note, createdAt |
| Budget | id, categoryId, month, limitKopecks |
| Goal | id, name, targetKopecks, deadline, status, description |
| GoalContribution | id, goalId, amountKopecks, date |
| Settings | id, currency, theme, locale, weekStartsOn |

Идентификаторы UUID. Уникальность Budget(categoryId, month). Ссылочная целостность всех связей. Тип категории соответствует типу операции. Для перевода два разных счёта, категория отсутствует. Все изменения переводов выполняются атомарно. Дата операции — YYYY-MM-DD без сдвига часового пояса; временные метки — UTC.

## 6. Контракт REST API

| Метод | Маршрут | Действие |
| GET | /api/v1/dashboard?month=YYYY-MM | Сводка |
| GET, POST | /api/v1/transactions | Список и создание |
| GET, PATCH, DELETE | /api/v1/transactions/:id | Операция по ID |
| GET, POST, PATCH | /api/v1/accounts[/:id] | Счета |
| GET, POST, PATCH | /api/v1/categories[/:id] | Категории |
| GET, PUT | /api/v1/budgets/:month | Лимиты месяца |
| GET, POST, PATCH | /api/v1/goals[/:id] | Цели |
| POST | /api/v1/goals/:id/contributions | Создать взнос |
| DELETE | /api/v1/goals/:id/contributions/:contributionId | Удалить взнос |
| GET | /api/v1/analytics | Аналитика |
| GET | /api/v1/export?format=csv/xlsx | Экспорт |
| GET | /api/v1/backup | Копия JSON |
| POST | /api/v1/restore/preview | Проверка копии |
| POST | /api/v1/restore/confirm | Подтверждение восстановления |

Ответы — JSON с полем data при успехе и error (code, message, fields?) при ошибке. Коды HTTP: 200, 201, 204, 400, 404, 409, 500. Обязательна серверная валидация Zod.

Локальный сервер на 127.0.0.1, ограниченный CORS, отсутствие секретов в репозитории; без публичного размещения до внедрения авторизации.

Операции перевода и восстановления атомарны. Обработка ошибок без потери данных.

TypeScript strict, lint, unit-тесты расчётов, E2E-тесты пользовательских сценариев, production build.

Никаких неработающих кнопок, заглушек в продуктивных расчётах и скрытого исполнения пользовательского ввода.

## 9. Критерии приёмки

Доход 10 000 ₽ увеличивает баланс ровно на 10 000 ₽.

Расход 2 500 ₽ уменьшает баланс и учитывается в лимите категории.

Перевод 3 000 ₽ между счетами не меняет суммарный баланс и не попадает в доходы/расходы.

Редактирование даты и суммы расхода обновляет отчёты за соответствующие месяцы.

Бюджеты двух месяцев не смешиваются; лимит 0 не вызывает деление на ноль.

Взнос в цель и его отмена корректно меняют прогресс без влияния на доходы.

JSON-резервная копия восстанавливает все связи и суммы.

Интерфейс проверен на ширинах 375, 768 и 1440 px.

Проходят typecheck, lint, unit, E2E и production build.

Проверены пустая база, превышение лимита, отрицательный баланс, повторное удаление, ошибочный импорт.
